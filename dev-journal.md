## 2026-09-14 02:45 — Historical backfill (Stage 0 / 0.3)

**Model:** claude-sonnet-5
**Pillar/task:** Roots / Group 0, phase 0.3 (Historical Backfill)
**What changed:** Built `backfill.py` (archive download + parsing for daily aggTrades/klines, CoinGecko top-200 symbol list, time-blocked dev/calibration/holdout split) and `backfill_job.py` (orchestrates the full ~12-month pull across all symbols, writes into the same Parquet layout the live recorder uses, logs the split boundary durably in the `experiments` table). Confirmed the 70/15/15 dev/calibration/holdout ratio with Omar directly — no ratio is stated anywhere in the docs (every doc says "time-blocked," none gives a number), so this was not guessed.
**Why:** `docs/architecture-review.md` §8b (backfillable-vs-not table, ~12 months, CoinGecko top-200), §7/§8 (splits, holdout-look discipline), `docs/implementation-plan.md` phase 0.3.
**Deviates from docs?:** the 70/15/15 ratio is Omar's explicit choice, not a doc value — flagged and confirmed rather than assumed, per `build-plan.md` §3 step 5.
**Verified by:** Two real bugs were found and fixed by testing against actual downloaded archive files rather than trusting my initial column-list assumptions: (1) the real aggTrades CSV has 8 columns including `is_best_match` (not 7) and no header row — my first version guessed 7 columns and a header, which crashed on the very first real file; (2) archive timestamps are in **microseconds**, not milliseconds like the live WS stream — confirmed by checking that the first trade of `BTCUSDT-aggTrades-2026-09-01.csv` resolves to exactly `2026-09-01T00:00:00`. After fixing both: downloaded and correctly parsed a full real day of BTCUSDT aggTrades (1,040,978 rows) and klines (24 hourly bars) with `DOGSHITCOINUSDT` correctly returning "not found" instead of crashing. Ran the full orchestration end-to-end (`backfill_symbol` + `log_split_boundary`) against 2 real symbols × 3 real days: 3,231,096 total trade rows written to Parquet with zero missing days, and the split boundary logged to Postgres `experiments`. That small-scale run also surfaced a third bug: `compute_split_boundary`'s naive rounding produces a degenerate (inverted) calibration block on a short date range (3 days -> 0 calibration days) — added a guard that raises `ValueError` instead of silently producing an invalid boundary; a real ~12-month run never approaches this edge, but the code no longer trusts that assumption silently. 46 pytest tests pass across the whole repo after these fixes. The full 200-symbol × 12-month run itself was not executed in this session (many hours, meaningful bandwidth) — the orchestration is proven correct at small scale against real data, not simulated.
